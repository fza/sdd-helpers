sdd-helpers releases through the same pipeline as agentic-helpers, and its first release is v1.0.0, cut only when Felix starts it.

The pipeline: the `release` workflow (`.github/workflows/release.yml`), started by hand from `main`, runs semantic-release (`.releaserc.yml`), which derives the version from the Conventional Commits since the last tag, writes it into `plugin/.claude-plugin/plugin.json`, tags that commit and opens the GitHub release as a draft; GoReleaser (`.goreleaser.yaml`) then uploads every binary and publishes the draft. Releases on `fza/sdd-helpers` are immutable, so nothing is added to a release once published. Before each release, `scripts/release-fixture` writes the fixture the release tests against, and `scripts/linux-test` runs every Go suite on Linux. The second pipeline to maintain is a cost the repository split accepted (20261107-093312-d-cpt-3aq).

v1.0.0 is semantic-release's default first version when no tag exists, so it needs no setup, and it is honest: the code is the gate and capture that already shipped in agentic-helpers v2.28.0 (20261107-094237-d-tac-imc).

Rejected: v0.1.0. It would say the programs are not stable yet, but it needs a hand-pushed base tag `v0.0.0`, and a breaking-change commit would still jump to v1.0.0 unless the commit analyzer's rules were tuned.

Accepted cost: every later breaking change means a new major version.

Pending: v1.0.0 is not yet cut. This decision is fulfilled once the release exists with its binaries published.
