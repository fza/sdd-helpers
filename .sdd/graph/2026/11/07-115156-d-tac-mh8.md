sdd-helpers deletes old release folders from the plugin's data directory once a day, keeping every version a session may still run, the way agentic-helpers does (github.com/fza/agentic-helpers:20261103-004231-d-tac-cjs).

The launcher `plugin/hooks/run` unpacks each release into `<data>/<version>/` and never removes one. In agentic-helpers the daily `agentic-helpers prune` deleted them; sdd-helpers took the launcher from agentic-helpers v2.28.0 (20261107-094237-d-tac-imc) but not that command, so every release, about 9 MB, now stays for good.

- **Kept:** the version `plugin/.claude-plugin/plugin.json` names; every version a running `sdd-` process executes a program from, read from the process table (sysctl on darwin, `/proc` on Linux); every version a SessionStart used within 14 days.
- **Use mark:** the launcher writes `<data>/<version>/used` at each SessionStart it runs a binary for.
- **Run:** `sdd-grounding-gate start`, at SessionStart, starts `sdd-grounding-gate prune` detached at most once a day, so no hook waits for it. The run records its outcome in `<data>/release-prune.json`, and a failed run is told once at the next SessionStart.
- **Removal:** only folders named as a version (`^[0-9]+\.[0-9]+\.[0-9]+$`), each renamed to `.pruned-<version>` and then removed through `internal/safefs`, so the launcher never finds half a version under its name; a `.pruned-` folder a crash left goes first.

A session still running an older plugin version runs that version's programs, and without them its grounding gate refuses every call, so a folder goes only once no session can need it.

Rejected:

- Keeping the newest three releases: a fixed bound, but a session left running on an older version loses its programs and its gate then refuses every call.
- The launcher deleting every other release folder after a fetch: shell logic that is hard to test, with the same loss for a session on an older version.
- Leaving the folders and documenting it: about 9 MB more per release, without end.

Accepted costs: up to two weeks of releases stay; one small file is written per SessionStart; a new mode `prune` on `sdd-grounding-gate`, and with it the process-table reading and detached start that agentic-helpers carries.

Acceptance:

1. After a prune run, the data directory holds only the named version, versions a running process executes from, and versions used within 14 days, shown by a test over a tree in `t.TempDir()` with a faked process table.
2. A folder not named as a version, and any file beside the version folders, stays.
3. A SessionStart through the launcher leaves `<data>/<version>/used` with a fresh modification time.
4. A second `start` within a day starts no second run, and a failed run's message appears at the next SessionStart once.
5. `docs/plugin/` describes the use mark, the prune run and `release-prune.json`.
