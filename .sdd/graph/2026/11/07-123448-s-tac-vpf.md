sdd-helpers now deletes old release folders from the plugin's data directory once a day, as the release prune decision (20261107-115156-d-tac-mh8) set out, and starts the run from `sdd-grounding-gate check` as well as from `sdd-grounding-gate start`, as its refinement (20261107-122339-d-tac-zgc) set out. Commit `c3a3603` on `main` carries both; machines get it with the next release.

Each acceptance criterion and the test that shows it:

1. A run keeps only the named version, versions a running `sdd-` process executes from, and versions used within 14 days: `TestARunDeletesOnlyTheReleasesNoSessionMayRun` in `internal/releaseprune`, over a tree in `t.TempDir()` with a faked process table.
2. A folder not named as a version, and any file beside the version folders, stays: `TestARunLeavesEverythingButReleaseFolders`.
3. A SessionStart through the launcher leaves `<data>/<version>/used` with a fresh modification time: `TestASessionStartMarksTheVersionItRuns`.
4. A second `start` within a day starts no second run, and a failed run is told once: `TestTheDaysClaimStartsOneRun`, `TestASessionStartStartsTheDaysPruneOnce` and `TestAFailedPruneIsToldAtTheNextSessionStartOnce`.
5. `docs/plugin/architecture.md` (section "Release pruning") and `docs/plugin/usage.md` describe the use mark, the run and `release-prune.json`.
6. `check` starts the day's run in a project without `.sdd/`: `TestTheMachineCheckStartsTheDaysPruneInAProjectWithoutAGraph`. The Hooks rule in `source/AGENTS.md` names the prune beside `check`, and the docs say the same.

Proof: `go vet`, `go test -race` on macOS, every suite on Linux through `scripts/linux-test`, and `claude plugin validate` on the marketplace and the plugin all pass. Each new guard was broken and its test failed on that guard's own assertion. The two checks keeping a failure to one warning mask each other, so they were broken together and then each alone. One guard is out of reach of any test: the darwin process-table read skipping a process that is exiting or a zombie, since a test cannot make one appear on demand.
