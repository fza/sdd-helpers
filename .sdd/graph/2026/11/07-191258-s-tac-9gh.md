`sdd-grounding-gate collapse` now hands Claude Code a shortened sdd answer as a plain JSON string under `hookSpecificOutput.updatedToolOutput`, with `<`, `>` and `&` left unescaped, released in sdd-helpers v1.1.1. Commit `6bfd008` carries the change; the `release` workflow cut v1.1.1 from it as run 42399678632, with release commit `84aaa27`. This closes the decision on the collapse output form (20261107-185320-d-tac-1o0).

Each acceptance criterion and what shows it:

1. A repeated `mcp__sdd__show` reaches the agent as the shortened JSON object, with no `content` wrapper and no escaped quotes: shown live in a Claude Code session whose hooks ran a build of `6bfd008` through `SDD_HELPERS_BIN_DIR`, where the chain entries already shown came back as `shown_earlier` pointers inside a plain object.
2. The output carries the answer as a string under `updatedToolOutput` and no `updatedMCPToolOutput` key: the collapse tests in `internal/grounding` fail on either key alone, on both keys together, and on the wrapper sent as the string.
3. Markup stays unescaped: `TestMarkupInAnAnswerStaysUnescaped` in `internal/collapse` fails wherever any piece that carries sdd's text goes through Go's default encoder again, for `show` and `view` answers alike.
4. `docs/grounding-gate/architecture.md` names `updatedToolOutput` and the plain-string form.
5. v1.1.1 is published with archives for darwin and linux on amd64 and arm64 and their `checksums.txt`.

**Deviations.** The release replay test compares every gate answer with what a committed release printed. A successor in it maps the collapse output earlier releases recorded under the content wrapper to the plain-string form, the one answer this decision changed on purpose; every other recorded answer still has to match byte for byte. The note line every collapsed answer gains stays encoded by `json.Marshal`: it is a fixed text with no markup, so routing it through the unescaped encoder would be a guard no test can fail.

**Correction.** The decision's body shows `<` in two places where it means Go's escape for it, `\u003c`: Go's default encoder adds `\u003c` for `<`, and a test fails on `\u003c`.
