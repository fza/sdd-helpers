sdd-helpers is a Claude Code plugin with two programs, the grounding gate `sdd-grounding-gate` and the capture command `sdd-capture`, each paired with a skill (`sdd-helpers:grounding`, `sdd-helpers:capture`) that tells the agent what it is doing. It is a temporary workaround for quirks of stock sdd (20261107-093312-d-cpt-3aq).

`sdd-grounding-gate` runs as hooks on every tool call that asks the owner, edits a draft or writes to the graph: it holds such a call until the session has searched the graph by meaning and by literal term, listed its topics, and read each entry it relies on together with the later entries that refine or replace it (an `sdd show` at the read depth the project sets). It also scans every graph write for credentials, keeps a project's topic prefix and draft lint in force on captures through sdd's own MCP tools, and shortens sdd output the agent was already shown. `sdd-capture` writes one graph entry from a draft file through the project's lint, sdd's pre-flight and the same credential scan, and deletes the draft once captured.

Installed once per machine, the plugin works in every project carrying a graph under `.sdd/` and stays silent elsewhere, but for the session-start check naming what is off on the machine. A project lifts the gate for itself with `enabled: false` in `.sdd/grounding.yaml`, which also carries its topic prefix, draft lint and read depths. Per machine, the plugin options `grounding_gate_enabled`, `capture_enabled` and `capture_remove_draft` switch the pieces; `sdd-capture` goes off with the gate.

Both programs came from agentic-helpers, where they were named `agentic-grounding-gate` and `agentic-capture` (github.com/fza/agentic-helpers:20261025-195434-s-cpt-ihb).

The repository is its own marketplace (`.claude-plugin/marketplace.json`). `plugin/` holds the plugin and nothing else: its manifest, `hooks/` with the wiring `hooks.json` and the launcher `run`, which runs the binaries of the release `plugin/.claude-plugin/plugin.json` names, `bin/` with the command `sdd-capture`, and `skills/`. The binaries are one Go module, `source/hooks`, one folder per program under `cmd/`. `README.md` says what the repository is and how to install it; `docs/` holds one folder per piece with `usage.md` and `architecture.md`, and is where behaviour is described in full.
