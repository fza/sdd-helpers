sdd-helpers keeps its own sdd graph under `.sdd/`, linked both ways with the agentic-helpers graph, and cites that graph's entries in place rather than copying them.

The repository is public and stands on its own (20261107-093312-d-cpt-3aq), so it carries its own record of why its programs are the way they are. Each graph lists the other under `dependencies` in `.sdd/config.yaml` (`github.com/fza/agentic-helpers` here, `github.com/fza/sdd-helpers` there), so a search or read from either side reaches both. The mutual link is safe: sdd's walk over a graph's dependencies keeps a set of graphs already seen, the starting graph included, so it never loops.

The graph starts with an actor entry, introduction entries and one decision entry per choice made in setting the repository up. The actor entry (20261107-092347-s-prc-xgm) is captured anew rather than copied: a copy keeps its id, and the same short id in two linked graphs makes it ambiguous which graph it resolves to. Entries about how the grounding gate and capture came to work as they do stay in agentic-helpers, under its topic `hooks/grounding-gate`, and are cited as `github.com/fza/agentic-helpers:<id>`, as this entry cites github.com/fza/agentic-helpers:20261025-195434-s-cpt-ihb.

Rejected:

- Seeding this graph with copies of the old gate entries. The same entries would exist twice, their refs to entries left uncopied would dangle, and their bodies, which can never be edited, name `agentic-*` binaries the code no longer has.
- No graph in sdd-helpers. A public repository would hold no record of its own reasons, and those reasons would live in agentic-helpers, a repository that now receives fixes only and no new work, so its graph is no home for decisions about a living codebase.

Accepted cost: to learn why the gate works as it does, a reader follows links into the agentic-helpers graph.

Settled: the graph exists and both links are in place, so nothing follows from this decision.
