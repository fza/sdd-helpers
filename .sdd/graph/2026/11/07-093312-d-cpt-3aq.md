sdd-helpers is a temporary workaround for known quirks of stock sdd, kept in a repository and Claude Code plugin of its own: the goal is to fix each quirk in sdd itself, and each piece of sdd-helpers retires once stock sdd no longer needs it.

The grounding gate and the capture command shipped before in agentic-helpers, as two pieces among unrelated ones. Both exist only because stock sdd lets an agent ask, draft and capture without having read the graph, and lets a capture bypass the project's rules for it. Kept in a repository holding nothing but these workarounds, each one stays ready to be turned into a fix for sdd without untangling it from pieces that have nothing to do with a decision graph, and a project using sdd installs what it needs and nothing else. Until stock sdd carries the fixes, the workaround serves the direction that agents work from graph reads, not belief (20261107-092827-d-stg-qsj). agentic-helpers' overview of its pieces (github.com/fza/agentic-helpers:20261025-195434-s-cpt-ihb) still lists the two programs; correcting it belongs to that graph.

This keeps applying to every later change: a feature belongs in sdd-helpers only as a workaround for a quirk of stock sdd, and the change that lets stock sdd do the same job removes the workaround rather than keeping both. Work that improves sdd-helpers without bringing its fix to sdd closer is weighed against that goal.

The surfaces this creates: the repository `github.com/fza/sdd-helpers`, which is its own marketplace `sdd-helpers` (`.claude-plugin/marketplace.json`); the plugin `sdd-helpers` in `plugin/`, installed as `sdd-helpers@sdd-helpers`; the Go module `github.com/fza/sdd-helpers/source/hooks`; and the environment variable `SDD_HELPERS_BIN_DIR`, which points a session at a checkout's own build. The plugin options keep the keys they had in agentic-helpers.

Rejected:

- Keeping both programs in agentic-helpers. They would stay tied to the release cadence and the review of unrelated pieces, a project using sdd would install all of them to get two, and turning them into fixes for sdd would first mean cutting them out.
- Waiting for the fixes in stock sdd and shipping no workaround. Projects need agents held to the graph now, and a workaround in use shows which fix sdd needs.

Accepted costs: a second repository and release pipeline to maintain, a second plugin for anyone who also uses agentic-helpers, a one-time move for existing users, who switch the two pieces off in agentic-helpers so no project is gated twice, and the work of removing each piece again once sdd fixes its quirk.

The program names, the code base the repository starts from, its release pipeline and the order in which agentic-helpers drops its own copies are decisions of their own.
