sdd-helpers v1.1.3 is released and carries the deprecation of sdd-helpers (20261110-145517-d-cpt-sdo): tag `v1.1.3` on release commit `aefee7d`, a GitHub release with archives for darwin and linux on amd64 and arm64 and their `checksums.txt`, cut by the `release` workflow from `main` at `7d800e2` as run 42831666988, following v1.1.2 (20261109-095300-s-tac-bpv).

It ships the deprecation in two commits:

- `0fadf12` opens `README.md` with a warning box and a "Deprecated" section, and deletes the section on moving over from agentic-helpers.
- `8542580` says at every session start that sdd-helpers is deprecated, through the standing-aside line where the pieces stand aside, makes both pieces, the grounding gate `sdd-grounding-gate` and `sdd-capture`, stand aside where `sdd config get verify.mode` prints a value other than `off`, changes the fork's install command to `brew install --cask fza/tap/sdd`, and updates the docs, both skills and the plugin and marketplace manifests to match.

Before the release, the binaries built from `8542580` ran in the sdd-helpers checkout, whose sdd is the fork reporting `verify.mode` `deep`: the session start printed the standing-aside line, a directory without a graph got the deprecation line, and `sdd-capture` refused, naming sdd's own capture.

Its release fixture, `source/hooks/test/fixtures/releases/v1.1.3/`, is committed in `a3af9c9`: the state and answers of v1.1.3's own `sdd-grounding-gate` through a scripted session, which later builds replay.
