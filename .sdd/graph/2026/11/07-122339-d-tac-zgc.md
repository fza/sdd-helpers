The daily release prune also starts from `sdd-grounding-gate check`, which runs at every SessionStart in every project, beside `sdd-grounding-gate start`, so every machine with sdd-helpers installed cleans up its old release folders.

The release prune decision (20261107-115156-d-tac-mh8) starts the run from `start`, which runs only in a project carrying `.sdd/` and only while `grounding_gate_enabled` is on. The launcher, though, fetches releases at SessionStart in every project, so a machine with the gate switched off, or one that never opens a graph project, would keep every release folder. `check` already speaks in every project, its work being the machine rather than the project, and the release folders are the machine's too. Each run first claims the day by recording its start in `<data>/release-prune.json` under a lock, so with both modes starting it only one run a day still happens, whichever mode reaches the claim first, and a failed run is still told once.

Rejected: starting only from `start`. It keeps every hook but `check` silent outside graph projects, but leaves those machines growing by about 9 MB per release.

Accepted cost: `check` gains a side effect, a detached prune at most once a day. The rule in `source/AGENTS.md` naming `check` as the one hook that works in every project now names the prune with it, and the docs say the same.

Pending: fulfilled with the release prune itself, once `check` starts the day's run and a test shows it doing so in a project without `.sdd/`.
