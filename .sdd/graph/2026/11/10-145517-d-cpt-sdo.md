sdd-helpers is deprecated: the fza/sdd fork from `v0.18.0-alpha.3.fza.43` does most of the work of both pieces (20261107-093513-s-cpt-qxc) itself, so users switch to it, or keep upstream networkteam/sdd without any gate, and uninstall the plugin `sdd-helpers@sdd-helpers`.

This is a deliberate exception to the retirement rule of the guiding directive 20261107-093312-d-cpt-3aq, which removes each piece once stock sdd does its job, and that directive stays as it is: the fza/sdd fork counts as sdd doing the pieces' job, though upstream sdd does not, and the plugin is deprecated rather than removed. The jobs the fork does not cover, listed below, are accepted costs, among them the reads before a question or a draft edit that the aspiration 20261107-092827-d-stg-qsj pulls toward. The fork's capture procedure holds a graph write until the reads made through `gather` inside the capture are complete, scans every entry and attachment for credentials, and takes a staged file as an entry's body through `bodyHandle`; across the session, its reads collapse output the session was already shown. Its `verify.mode` (`off`, `grounding`, `prose`, `deep`) sets how much it checks.

What the fork does not cover is named in the README, so nobody switches blind: reads owed before a question or a draft edit (the fork gates the capture only); a pre-flight falling back to other models (`llm.retry.*` retries one model); a capture from a draft file on the command line (`sdd new` takes no body file); deleting draft files an agent writes itself; the `listing_prefix` topic rule and `draft_lint`, which an sdd hook on `capture.assemble` replaces. Upstream sdd carries none of the fork's checks.

The patch release v1.1.3 carries the deprecation to agents and users:

- `README.md` opens with a warning box and a "Deprecated" section: how to switch (`brew install --cask fza/tap/sdd`, `install.sh` with the release tag, `claude plugin uninstall sdd-helpers@sdd-helpers`) and what the fork does not cover. The section on moving over from agentic-helpers is deleted, since it sent readers to a deprecated plugin; agentic-helpers removes its own pointers to sdd-helpers in its next release.
- `sdd-grounding-gate check` prints a deprecation line at every session start, in every project. The line informs; it does not tell the agent to relay it.
- Where `sdd config get verify.mode` prints a value other than `off`, both pieces stand aside: the gate lets every call through, records no reads and collapses nothing (`end` still removes the session's ledgers), `sdd-capture` refuses and names sdd's own capture, and the session-start line says so. A second gate on top of the fork's only costs reads the fork does not credit, and can stall the fork's capture, since the gate hooks `start_procedure` and `next`. The mode is read, never the version: earlier fork releases carry the fork's version suffix without the gate.
- The fork's install command becomes `brew install --cask fza/tap/sdd`, in the code and the docs.

Rejected:

- A deprecation notice alone, the gate unchanged: both gates would run alongside the fork until users uninstall.
- Switching both pieces off everywhere: users of upstream sdd would lose the gate and the credential scan before they decide to switch.
- Telling agents to pass the line on to the user in every session: one more line in every session's first reply, in every project.
- Rewriting the whole README as a notice: the options reference stays useful while the plugin stays installed.
- Reading the fork's planned `verify.kinds` (a mode per entry kind, gating those kinds even under `verify.mode: off`) already in v1.1.3: the key is not built yet, and what it prints for an empty map is unknown.

Accepted costs: users of upstream sdd who uninstall lose the gate and the credential scan, which keep working for them while the plugin stays installed, since the deprecation advises uninstalling whichever sdd is kept; one `sdd config get` per hook call; until a later patch reads `verify.kinds`, a project with `verify.mode: off` and kinds set runs both gates on those kinds; agentic-helpers v2.29.0 (20261107-114225-s-tac-96h) still tells users to install sdd-helpers until its next release.

The directive is fulfilled once v1.1.3 is released. Reading `verify.kinds` is a decision of its own, taken once the key ships.
